# 下一里程碑设计：补齐历史股票池行情（已批准）

状态：`APPROVED_FOR_FULL_RUN`。2只股票端到端试验已完成；用户于2026-09-04批准进入历史沪深300价格量选股MVP，全量顺序抓取获准启动。

## 事实

- BaoStock周频历史成分从2006-01-04至2026-08-31共出现940只不同股票。
- 旧项目复制来的不复权历史覆盖其中428只；现有前复权标准层只覆盖其中300只。
- 因此当前300只股票不能代表历史沪深300。现在运行长期选股回测会产生严重幸存者偏差，收益结果不能作为策略证据。
- BaoStock单次长历史查询存在2000行分页后静默截断风险；短于2000行的窗口本次实测稳定。

## 目标

为940只历史成分建立同一来源、同一批次、可恢复的分段日线原始快照，同时保留：

- `adjustflag=3` 不复权价格，用于成交限制、涨跌停判断和未来虚拟盘价格语义；
- `adjustflag=2` 前复权价格，用于研究收益和价格型因子；
- 每个代码、复权口径和时间段的查询参数、行数、日期范围、文件大小和SHA256；
- 空区间、上市前区间、退市后区间和查询错误的不同状态，不把空响应自动解释成无交易。

## 实施方案

1. 股票集合固定为已封存历史成分快照中的940个唯一代码，并把该输入文件哈希写入运行状态。
2. 每只股票按三个不超过2000个交易日的窗口查询：`2010-01-01~2015-12-31`、`2016-01-01~2021-12-31`、`2022-01-01~当前已验证交易日`。
3. 两种复权口径分别保存分段原始文件，不在抓取阶段拼接。
4. 每25次查询主动更换会话；瞬时错误最多重试4次，之后停止。`run_state.json` 逐文件记录完成状态，允许从已核对哈希的文件恢复。
5. 独立校验要求预期任务全部有明确状态、非空文件日期单调且唯一、同股票双口径日期和成交量一致、任一文件不得出现疑似2000行截断。
6. 只有完整快照状态为 `SEALED` 且独立报告为 `PASS`，才生成标准层V2；否则保持原始证据，不进入回测。

## 标准层V2边界

- 不跨来源拼接同名的前复权价格水平；若必须跨批次衔接，只能在重叠区间验证收益一致性后拼接收益，并记录接缝。
- 研究回测使用前复权收益；成交可行性判断使用同一股票同一批次的不复权字段。
- 历史成分按可证明的生效日期使用；周频空洞对应区间保持不可用。当前唯一已知空洞在2007年，早于V1股票行情起点2010年，但仍保留在质量报告中。
- 财务因子继续关闭，直到公告首次可用日完成更大样本和官方公告核对。

## 工作量、风险和代价

- 任务量为5,640次顺序查询。2只股票、12个任务的实测为76.2秒，按线性折算全量约9.9小时；免费接口断线时会更久。原先1至2小时的估计已被实测推翻。
- 试验数据2只股票约2.0MB，线性折算全量约0.94GB，且不适合提交Git。
- BaoStock可能回修历史或改变复权结果；封存哈希只能证明本次获取内容，不能证明数据源永不变化。
- 940只只解决沪深300历史成分范围，不等于全A股选股池。
- 完成数据补齐仍不证明策略有效；之后还需另行批准回测、策略、风控和虚拟盘设计。

## 批准闸门

原方案已批准，抓取器和独立校验器也已通过2只股票试验；但实测成本发生重大变化，全量启动前需要重新确认。可选路径：

1. 继续顺序全量：约9.9小时，接口风险最低，推荐；
2. 改为多会话并行：理论上约2.5至4小时，但限频、断线、分片合并和一致性风险更高，需要增加开发和验证；
3. 只抓2010年以后实际入选过的800只：约8.4小时，节省有限，并放弃140只早期成员与固定940只任务清单的一致性。
