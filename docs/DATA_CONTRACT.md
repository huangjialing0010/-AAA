# 数据契约（第一版）

## 数据分层

- 原始导入层：`data/imports/`，内容不可改写，只用于追溯和重新处理。
- 标准数据层：`data/canonical/`，由新项目转换生成，必须能追溯到原始文件和转换版本。

## 本次导入白名单

1. 明确标记 `qfq` 的300只股票日线；每只股票只取最新文件。
2. 原始历史财务 CSV。
3. 交易日历、沪深300基准、当前沪深300成分快照、当前申万行业映射。
4. 31个申万一级行业指数历史文件。

账户、订单、持仓、候选、绩效和策略输出禁止导入。

旧版无 `qfq` 标记日线原本因复权语义不明而禁止导入。2026-09-03完成跨来源核验后，只允许按 `docs/DECISION_20260903_UNADJUSTED_DATA_SOURCE.md` 的规则复制为独立“不复权候选快照”；在质量验证完成前不得进入标准层或回测。

## 已知限制

- 标准层股票日线仍截止2026-08-07；近期原始快照已到2026-09-02，但在交易日历、拼接边界和复权语义验证完成前不得直接并入标准层。
- 已取得2006-01-04至2026-08-31的周频沪深300历史成分响应，但2007-07-23有一个覆盖缺口，且尚未与中证指数官方公告核对；缺口和生效区间解决前不得直接作为正式历史股票池。
- 财务原始表只有报告期，没有真实公告日期。东方财富 `UPDATE_DATE` 与BaoStock `pubDate` 在4条抽样记录上吻合，但全量快照存在220行与 `NOTICE_DATE` 不一致；300774更正案例证明同一报告期会出现不同披露/修订版本。`UPDATE_DATE`、`NOTICE_DATE`、`EITIME` 均不得单独命名为正式 `available_date`。正式点时数据须保留证券、报告期、字段、版本和值的事件历史，并核对权威公告原文及首次可交易决策时点。
- 财务公告版本事件的数据契约草案见 `docs/FINANCIAL_DISCLOSURE_EVENT_CONTRACT_V1.md`。在小样本原文与版本复核、来源条款检查及独立质量验证完成前，`financial_disclosure_events_v1` 不得创建为正式标准层，也不得替代 `available_date_assumed`。
- 财务来源自动化采集授权尚未确认：东方财富产品协议包含数据使用限制，Choice许可明确限制从该产品服务器爬取；巨潮目前已查到的App隐私政策不等同数据再利用许可。不得因历史上已有少量试验快照而扩大抓取或分发。
- 财务字段存在多种结构，`False` 表示缺失，不得填0。
- 行业映射是当前快照，没有历史生效区间。
- 沪深300基准早期历史、成交量为0记录和来源口径需要再次确认。

## 正式回测准入

数据只有同时满足以下条件才可从原始导入层进入标准数据层：

- 字段、类型、单位和复权口径明确；
- 证券代码和日期唯一；
- 来源文件、SHA256和转换版本可追溯；
- 财务数据具有可用日期；
- 股票池和行业分类具有历史生效日期，或明确声明只用于当前截面；
- 质量校验失败时阻断，不静默删除或填补。

## 标准层 V1

标准层的具体字段、时间语义和质量闸门见 `docs/CANONICAL_DATA_DESIGN.md`。V1 已确定以下不可变规则：

- 股票日线只使用导入快照中的前复权数据，并显式写入 `adjustment=qfq`；
- 不复权候选数据必须与前复权数据分目录存放，显式写入 `adjustment=none`，不得互相覆盖；
- 财务 `False` 和空值一律保留为空，不得当作 0；
- 财务可用日期是保守代理，不冒充实际公告日期；
- 当前股票池、行业映射和行业估值截面都写入 `historical_use_allowed=false`；
- 标准层生成清单必须包含输入清单哈希和每个输出 CSV 的哈希。
