# 目标对账与低频投资框架修订提案

日期：2026-09-30。状态：已完成远程源码与保存日志核查；策略提案未生效。本文不修改旧账户、冻结规则或收益记录。

## 一、目标与交付

用户目标：少量持仓、中长期、低频手工操作；系统完成研究、候选筛选、可审计模拟交易、报告及复盘。盈利是待检验假设，程序运行成功不是盈利证据。资金和风险容忍度仍未知，不把研究资金视为真实投资承诺。

成功交付须同时具备：
1. 每个正式推荐能解释企业盈利、价格吸引力、入场依据、反面证据、失效条件、仓位及下一复核点。
2. 推荐绑定订单；模拟账户能连续完成买入、持有、退出、费用及公司行动记账。
3. 用户从仓库首页直接看到日期、运行健康、建议动作、持仓与全账户表现。
4. 失败有异常报告；缺数据不等同无机会；没有成交不等同系统失败。
5. 策略有效性与软件正确性分别验收。

## 三、先修运行，不改变投资规则

实施次序及验收：
1. 显式bash与pipefail，保存子步骤返回码；异常时仍上传诊断。找不到本批有效报告必须报错，不能沿用旧报告冒充今天。
2. 核对所需目录并创建允许的输出父目录；修复Windows输出UTF-8解码。Linux锁须保持排他、崩溃释放及重复执行幂等，不可简单移除锁。
3. 清点首批run、reference、盘前资格、相关来源与完整事件依赖。复制并校验必要证据；不得仅上传manifest而遗漏其绑定文件，也不得编造缺失开户记录。
4. 只读重放本地旧账与云端恢复账，现金、股数、费用、事件哈希全部一致后接续。当前本地执行工具不能启动，无法完成真实证据包导出与本地验证；GitHub接口可用但不能替代本地缺失证据。
5. 串行接入已批准的持续账户方案：风险审查、到期订单、报价/资格绑定、执行、公司行动、估值、对账、报告。一次执行使用明确的来源路径，不靠“最新目录”猜测。
6. GitHub作为唯一正式写账端；本地默认只读复盘或隔离测试。故障切换须确认最后可信事件，避免本地与云端各写一套账后混合收益。
7. 仅发布白名单报告和必要审计文件，替代git add -A；公众仓库避免无意上传调试文件。latest是入口，历史报告按批次保留，不能只覆盖latest。
8. 清洁检出环境验收：缺证据故障、无机会日、合理拒单、模拟买入持有卖出、重复运行、中断、跨日、分红及异常估值。合成交易与真实前向账户分开。任何一步失败不能生成成功运行结论。

报告入口：README链接reports/latest；运行状态独立于账户日报，显示最后成功业务日期、当前缺口与最后可信账本。不能为有报告而伪造账户数字。

## 四、策略修订：先判断生意与价格，再决定交易

以下为未来版本研究方案，不覆盖现有L1/R1，不自动启用新阈值。
完整性通过对收入、成本、现金、负债、估值和执行的影响检查，不靠堆砌新闻维度。

| 层面 | 关键问题 | 候选数据与证据 | 决策用途 |
| --- | --- | --- | --- |
| 宏观、利率、信用与资金 | 需求、融资、折现率和流动性如何作用于公司 | 官方统计、央行发布、公司披露 | 情景分析；未经验证不新增大盘择时硬门槛 |
| 政策、监管与制度 | 文件是否生效，受益环节是谁，利益能否留在企业 | 正式文件及生效日、监管披露 | 确认资格或重估假设；利好标题不直接产生订单 |
| 地缘、贸易、汇率与供应链 | 收入和关键投入暴露在哪里，有无替代路径 | 官方措施、年报地域/供应商披露 | 下行情景、集中风险和事件触发复核 |
| 行业供需、库存、产能与周期 | 盈利改善来自真实需求还是短期涨价/产能紧缺 | 有口径的行业统计、公司销量价格库存 | 识别周期利润；不能只用低PE认定低估 |
| 商业模式与竞争 | 客户为什么购买，提价和复购靠什么 | 年报分部、竞争格局、客户集中度 | 建立持有逻辑和可证伪指标 |
| 财务、治理与资本配置 | 利润是否变现金，债务与再融资能否承受 | 原始公告财报、审计、质押关联交易披露 | 资格、风险及股东回报能力 |
| 估值和隐含预期 | 当前价格需要多乐观的假设才能合理 | 当时可用财务、历史与可比估值 | 保守/基准/乐观区间，不伪装精确目标价 |
| 催化、预期差与期限 | 为什么可能在持有期兑现，已被价格反映多少 | 可核验事件日程及经营指标 | 设复核点；不能确认则降低判断置信度 |
| 价格、流动性与执行 | 左侧/右侧触发是否满足，实际能否成交 | 原始行情、复权因子、状态与限制 | 入场及模拟撮合 |
| 组合和用户适配 | 股票是否共同暴露于同一宏观风险，执行是否省事 | 当前持仓、产业暴露、操作次数 | 仓位、集中度与时间负担 |

证据记录统一字段：来源URL/文件哈希、发布时点、实际采集时点、决策截止时点、适用公司、事实摘要、作用路径、反面证据、关键缺口、复核日期和失效事件。
截至信号时未公开的信息不得用于当时决策；后续收集只可验证事先定义的成交事实，不倒灌为入场理由。

判断类型：
- 已确认硬风险：依据现有明确规则阻止新开仓；持仓按规则产生风险处理订单，不能假装已退出。
- 关键缺证：若直接决定投资逻辑或成交资格，候选进入REVIEW；记录补证动作。
- 非关键未知：保留不确定性，不因无关指标缺失无限阻塞全部候选。
- 研究观点：与事实分开，需结构化理由；不允许AI凭新闻语气填写true。

## 五、两类投资假设与研究边界

左侧：企业仍有持续经营与现金创造能力，价格反映过度悲观，且存在可检查的价值修复路径。需写清“为何不是价值陷阱”、正常化盈利、融资压力、反面情景。下跌幅度只是筛选条件之一。
右侧：经营或行业证据支持改善，价格确认配合，估值未透支合理预期。需写清“为何不是短期热度”、增长持续性、失败信号。
允许两类同时研究，不要求各买一只；维持预先登记的分类和排序，不能事后改标签。

V1的PE分位、突破、现金流/ROE与12%等数值仍是研究假设。第一阶段不凭更全面叙述新增大量权重；保留基线，在独立影子版本逐项验证新增分析是否改变决策且改善结果。
行业差异需单独说明：强周期利润应检查周期正常化；高杠杆公司ROE不等于质量；行业排除可能错过机会，保守规则存在机会成本。
金融股等超出原范围的扩展另提版本，不静默并入。

## 六、每日运行与用户看到的内容

每日更新行情和持仓风险；常规新仓仍按原周度节奏评估，不因每天出报告而每天交易。新财报或重大事件触发提前复核。
每份候选卡含：公司及盈利来源、行业与外部暴露、买入论据、最强反对意见、估值假设、LEFT/RIGHT、失效条件、证据截止、下一检查点。
正式推荐只从账户已登记订单生成，显示编号、有效时间、模拟数量与预算、成交模型、等待/拒绝/到期/成交。研究观察与正式推荐分别显示。
日报顶部直接回答：今天要关注什么，账户发生什么，哪些数字可信；无机会和无法筛选必须分别标注。
周报检验规则执行与手工负担；月报检验投资论点与收益来源。策略调整只形成提案。

## 七、评价标准与停止条件

软件验收不依赖盈利：状态完整、对账正确、事件唯一、证据时点有效、报告可读。
投资研究预登记：全账户扣费及含分红口径、基准口径、回撤、损失持续期、单股贡献、左右侧贡献、操作次数、延期及成本敏感性；不以胜率单独评价。
至少需要自然形成的完整持有退出回合、连续有效净值及不同情景证据。观察几个月不自动构成有效；少持仓造成样本少，不能用数笔高收益宣称长期优势。
正式晋级的收益/回撤/样本阈值尚未冻结；在独立评价前登记，用户真实风险偏好未知时不生成实盘适配结论。
反例：利润只依赖单只股、卖不出却记退出、旧价估值、异常集中暴露、操作负担超约束，均不能凭总收益晋级。
不存在足够证据时结论为继续观察/重设假设，不靠降低门槛制造成交。

## 八、下一交付顺序与风险代价

P0：修复假成功与异常可见性，恢复完整证据及单一持续账户。
P1：在原股票池中实现带完整证据卡的候选生成；先记录新增分析的影子判断，冻结后才允许影响正式订单。
P2：连续报告和完整交易回合，区分数据、执行、投资假设问题。
P3：依据事前标准复盘、提出并验证修订；不自动实盘。

新增行业研究带来数据成本与主观误差；多条件过滤可能长期空仓；少持仓放大个股风险；止损无法保证损失上限。保留这些代价并报告，不用复杂度掩盖尚未验证的盈利假设。
本次交付为可审查设计与真实审计；尚未修复运行器、上传开户证据或启动新版模拟账户。
