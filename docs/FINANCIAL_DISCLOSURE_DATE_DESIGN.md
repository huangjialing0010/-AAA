# 财务披露日期补齐设计（V1）

## 问题

旧财务数据只有 `报告期`，没有真实公告日。把报告期当成可用日会产生未来数据；固定延迟只能保守降级，不能证明真实披露时间。

## 候选来源

### 东方财富季度业绩报表

- 页面：https://data.eastmoney.com/bbsj/202003/yjbb.html
- 接口报告名：`RPT_LICO_FN_CPD`
- 关键字段：`SECURITY_CODE`、`REPORTDATE`、`UPDATE_DATE`
- 接口按报告期分页返回全市场，从2010年一季报开始可查询。
- 准入必须限定 `SECURITY_TYPE_CODE=058001001`。实测接口按报告期查询会混入B股和新三板等证券，2025年报返回11,492条；接口不接受报告期与证券类型的组合过滤，因此原始响应完整抓取后由客户端只保留A股范围（含沪深北市场），同时在清单中保留各证券类型的来源计数。

优势是每个报告期只需若干分页请求，比逐股票逐季度查询少两个数量级。

### BaoStock 盈利能力

- 接口：`query_profit_data(code, year, quarter)`
- 关键字段：`statDate`、`pubDate`

它适合做抽样交叉验证，但全量约需五万余次调用，不作为首选批量来源。

## 2026-09-28 小样本复核补充

已对东方财富快照中000001、600000两个代码的2025年报和2026年半年报，共4条记录，与BaoStock `pubDate` 对照：四条 `UPDATE_DATE` 与 `pubDate` 日期相同，`NOTICE_DATE` 也相同；`EITIME` 为晚间时间或前一晚。样本记录与巨潮资讯报告文件日期及浦发银行官网定期报告列表大体相符。该小样本只说明字段在这4条上相符，不能证明全市场、所有报告类型或修订数据都遵循同一规则。

随后对两个完整报告期快照（2025-12-31及2026-06-30，共11,130行）统计字段日期：`UPDATE_DATE` 与 `NOTICE_DATE` 不同的有220行（分别209/5,565和11/5,565）；`EITIME` 日期比 `NOTICE_DATE` 早一天的有10,356行，日期相同771行，另3行较晚。301689行的 `NOTICE_DATE=2026-03-31`、`EITIME=2026-03-31 15:59`、`UPDATE_DATE=2026-09-03`，再次说明 `UPDATE_DATE` 不是首次公告时间。

三条较晚样本中，300774已找到明确版本事件：2025年报首次文件于2026-03-17披露；公司于2026-04-03召开董事会审议前期会计差错更正，并在2026-04-04发布更正后的2025三季报和年报。首次年报的合并归母净利润为81,350,998.06元，更正后为84,098,775.98元；东方财富当前行已是更正后数值，却仍保留 `NOTICE_DATE=2026-03-17`，同时 `EITIME=2026-04-03 19:55`、`UPDATE_DATE=2026-04-04`。这是明确的点时偏差：若把当前值按 `NOTICE_DATE` 回填，回测会提前约18天使用后来修订的数据。详见[首次年报](https://static.cninfo.com.cn/finalpage/2026-03-17/1225012829.PDF)、[更正公告](https://static.cninfo.com.cn/finalpage/2026-04-04/1225079957.PDF)及[更正后年报](https://static.cninfo.com.cn/finalpage/2026-04-04/1225079960.PDF)。

001389的 `NOTICE_DATE=2026-02-28` 对应公司官方“2025年度部分财务数据自愿性披露公告”，公告明确说明数据未经最终审定；正式年报在2026-03-28披露。该行 `EITIME=2026-03-13`、`UPDATE_DATE=2026-03-28`，三个日期对应的数据版本/字段语义尚未完全解释。603139年报于2026-04-24披露，样本 `NOTICE_DATE` 和 `UPDATE_DATE` 均为4月24日，但 `EITIME=2026-08-21`；本轮尚未定位与该时间戳对应的更正/财报公告，标记 `REVIEW`，不得据此推断具体原因。

因此不能只选 `NOTICE_DATE`、`EITIME` 或 `UPDATE_DATE` 之一并用作最终点时日期。至少需要按“证券、报告期、字段、原始公告版本”保存数值和发布日期；公告或更正发布时追加新版本，不覆盖旧版本。当前东方财富快照适合横截面/字段研究，不足以恢复完整历史版本。

时间使用必须考虑交易时段：若公告在收盘后或非交易日发布，不得按发布日收盘价生成信号；应保存原始时间戳和时区，并把信息最早应用到公告之后的首个可交易决策时点。只有日期、没有时分秒时，保守地从公告日期之后的首个交易日开始使用。

## 时间语义判定

`UPDATE_DATE` 暂命名为 `candidate_disclosure_date`，不能直接命名为“首次公告日”。原因是数据源字段可能反映最新更新或修订日期。

只有满足以下条件后才能写入正式 `available_date`：

1. 日期/时间晚于对应 `REPORTDATE`；
2. 对 `NOTICE_DATE`、`EITIME` 与 BaoStock `pubDate` 做多年度、多报告类型、多交易时段抽样，差异可解释；
3. 再抽样核对巨潮资讯、交易所或公司正式披露档案的首次公开原文及修订公告；
4. 有多个公告/更正版本时保留每个版本的发布时间和数值，不以后续修订值回填早期历史；
5. 统一交易日映射、盘中/盘后可用规则，并用有先后顺序的事件测试验证。

验证前，标准层继续使用现有保守估算，不得静默替换。

## 风险和代价

- 网页接口没有稳定性承诺，字段和分页结构可能变化；结构异常必须终止。
- `UPDATE_DATE` 可能晚于首次披露日，直接使用会让信号滞后；若误解为更早日期则可能产生未来数据。
- 全市场季度文件体积较大，原始快照不得进入 Git。
