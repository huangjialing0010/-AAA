# 手工低频虚拟盘：规则修订与报告复盘闭环 V2

日期：2026-09-28。状态：用户已同意推进的设计，尚非可执行策略定稿。

## 1. 目的与边界

以少持仓、低频、用户能手工执行为约束，检验左侧与右侧机制；不把增加交易次数或提高回测收益作为系统完成标准。不接实盘。

保留原策略草案和冻结证据，不修改旧日志、旧计划及其哈希。新规则只对未来的新版本生效。此文规定后续实现；现有 V1 初始化器未自动升级。

## 2. 对原规则的修订决定

- 启动：冻结可执行版本后，使用当时已公开的最新数据重新检查整个允许股票池。持续满足条件的股票也可生成新信号；不要求先失效再触发。旧观察信号不直接转成交，不回填冻结日前交易。信号后下一可交易时点撮合，停牌、涨跌停、T+1和交易单位仍须检查。
- 范围：第一条可执行主线保持主板；创业板候选保留研究标签，不进入该账户。未来扩大范围需用户确认账户权限。
- 资金：5万、10万、20万元是研究情景，不是用户资金承诺。不为容纳昂贵股票提高账户资金；按整手、费用和仓位约束无法下单时记录拒绝。
- 风险参数：撤回无证据的15%止损、PE50%退出、单周跌破均线等替换。原草案12%、PE60%、连续两周均线退出也只是待检验假设，不因撤回替换就自动获得有效性。定稿必须给出完整可编码规则和预先登记的少量敏感性对照。
- 左侧：低估值和跌幅只构成候选，不构成价值确认。必须核对盈利恶化、现金流、审计及重大风险；无法确认时标记缺证并阻止相关入场。不得将每股现金流比率冒充总现金流比率。
- 估值退出：PE上升可能由盈利下降造成，必须拆分价格与盈利变化；盈利恶化归入风险退出研究，不能直接称为止盈。
- 仓位：区分首次仓位、加仓条件、单股上限、总仓位上限；未写明加仓规则不得加仓。低仓位账户必须同时披露现金占比，不能只报持仓收益。
- 频率：周度常规决策与每日风险检查分离；风险退出不受常规操作次数限制。止损阈值不是最大损失保证，跳空和无法成交可能造成更大损失。

## 3. 记录与报告契约

业务账本是唯一事实来源，报告不得自己补订单或成交。每份报告记录版本、账户ID、报告区间、生成时刻、数据截止日、账本截止日、来源清单及哈希、校验状态。

事实、判断、建议分栏。未开户记“未启动”；已开户无交易且账本齐全才可报告实际零收益；缺估值或未对账记“不可计算”，不得填零。报告生成时间不等于行情日期。

| 频率 | 用户需要看到的内容 |
| --- | --- |
| 日报 | 买卖/未交易原因；信号、订单、成交、拒绝和撤单分别计数；价格、股数、费用；持仓、现金、总资产、当日及累计损益；风险与数据缺口 |
| 周报 | 汇总日报；周收益、累计收益、回撤、基准比较、仓位；左右侧归因；未成交原因、人工操作次数和下一周观察事项 |
| 月报 | 汇总完整月份；已实现/未实现损益、费用、分红和完整交易轮次；集中度、左右侧贡献、执行偏差；本月复盘及版本决定 |

尚未结束的周/月只能标注“截至某日的周内/月内报告”，不得冒称完整周期。节假日无行情更新也须解释，不编造当日交易。交易日使用经验证的交易日历，不凭工作日推断。

主指标为扣费后的全账户收益。无外部资金流时以期末总资产/期初总资产-1计算；有外部资金流则先实现并验证分段时间加权收益，未实现前不输出可比收益率。净损益须扣除净入金。回撤按完整逐日净值序列计算，缺口显式披露。

同时展示现金占比、投入部分的损益贡献；投入部分收益率须明确分母和资金流处理，未实现时不输出。比较基准使用同期间、清晰标明价格/含息口径的系列；口径不匹配时标记限制，不直接宣称超额收益。现金仓位对比较的影响必须解释。

## 4. 自动复盘不等于自动改正式策略

流程：冻结版本 → 产生信号 → 模拟撮合 → 对账 → 报告 → 复盘 → 候选改进 → 独立验证 → 晋级或保留原版。

- 每日：数据时效、对账、异常订单、约束违例检查。失败时停止受影响交易并出异常报告，保留最后可信净值，不用旧价冒充新价。
- 每周：核查执行是否符合规则、操作量是否适合手工、拒单及偏差原因。不得据单周盈亏调参。
- 每月：区分数据故障、实现错误、执行限制与策略假设失效。样本不足输出“证据不足，继续观察”，允许维持原策略或空仓。
- 每项候选改进记录问题证据、假设、拟改字段、风险代价、版本、冻结时间、测试样本和失败标准；记录尝试总数，包括失败实验。
- 在独立影子账户检验候选版本；未触碰的样本外数据一经使用即登记，不重复宣称首次样本外。正式账户不被候选回测收益自动覆盖。
- 晋级前必须预先约定最低观察期、交易轮次及风险/执行门槛，做成本、集中度和参数稳定性检查；这些数值尚未冻结，不允许先看收益后设门槛。
- 正式策略切换、持仓数量/风险上限明显改变、扩大板块权限或进入实盘需用户决策。数据修正不得抹去原报告，生成更正版本及差异说明。

风险与代价：少持仓提高个股风险，低频使验证耗时更长；自动复盘容易产生事后解释和过拟合，因此允许“不改”。版本化、独立账户和审计增加维护成本，但保留可验证性。

## 5. 调度设计与实施顺序

自动调度尚未创建，不视为已在后台运行。计划使用 Asia/Shanghai 时区：每日20:00运行数据/账本检查与日报，周五同次生成周内报告，月末同次生成月度报告；依据交易日历确定最后交易日。休市日只检查是否需补数据/更正，不重复产生交易。

调度必须幂等：以账户、版本、区间、数据快照标识报告与交易批次；重试不得重复成交。失败留痕，不绕过准入。报告统一留在本项目，不默认发送飞书、邮件或其他外部渠道。

实施顺序：

1. 冻结可执行策略与准入缺口清单，包括入场、退出、资金情景、费用、整手、公司行动及启动重检；先不追求新增数据规模。
2. 复用已验证的撮合/股数账本组件，补足当前策略接口并测试，生成第一批真实模拟订单（允许合理拒单），禁止虚构成交。
3. 实现纯读取账本的日报、周报、月报生成器和校验；覆盖未启动、无交易、亏损、分红、拒单、缺数据、未完整周期与重复运行。
4. 验证报告与账本一致后启用自动调度、故障提示和月度复盘；自动输出候选提案，不自动晋级正式版本。

目录：沿用 `src/ashare_lab/selection/` 存放业务实现，`tools/`仅编排，`tests/`保存验证。后续报告目录采用 `reports/manual_paper_<UTC时间戳>/`，内置manifest和日/周/月子报告；只追加，纠错另建目录引用前版。候选提案置 `docs/`，名称含日期和版本。不得清理删除历史证据。
