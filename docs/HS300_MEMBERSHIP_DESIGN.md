# 沪深300历史成分设计（V1）

## 目的

建立按历史时点可查询的沪深300成员快照，替代“把当前300只倒灌到过去”的错误做法。

## 抓取粒度

BaoStock 的成分接口按周更新。实测2005年历史日期返回空响应，2006-01-04起稳定返回300只，因此V1只能从2006-01-04开始，在本项目交易日历中选择每个 ISO 周的第一个交易日进行查询，并保留：

- `query_date`：本项目实际发起查询的历史日期；
- `updateDate`：数据源返回的成分更新日期；
- `code`、`code_name`：当期成员。

同一个 `updateDate` 可能被多个 `query_date` 重复返回。原始层保留全部查询响应；标准层后续按 `updateDate + code` 去重，并构造生效区间。

## 准入和阻断

- 每次响应成员数必须在250到350之间，代码不得重复；
- 返回的 `updateDate` 不得晚于 `query_date`；
- 跨年份成员集合必须发生变化；
- 完整快照至少包含100个不同的源更新日期、30套不同成员集合；30套下限依据约20年间常规半年调整应显著超过该数量，而不是把每周响应误当成每周换仓；
- 空响应、接口错误或日期倒置直接终止；
- 若完整抓取中遇到个别空响应，则原始快照继续抓取但标记为 `SEALED_WITH_GAPS`，空日期写入 `coverage_gaps.csv`；不得静默用前一周填充，缺口解决前相关日期不得进入正式回测；
- 在完整性验证前，不生成历史生效区间，不用于回测。

## 风险和代价

- 周频接口可能遗漏周中临时调整；需要后续与中证指数官方调整公告抽样核对。
- 2005年缺少可用响应，因此该年不能基于本来源做历史沪深300成员回测。
- 实测2007-07-23至2007-07-27整周为空，而前后周均有300只；这类源端空洞必须显式保留，后续用中证指数官方资料补证。
- 免费接口无法证明历史记录没有回修，因此每次抓取时间和文件哈希必须保留。
- 约需一千余次顺序查询，按当前实测速度可能需要20分钟以上。
