# 手工低频策略持续模拟闭环实施方案

状态：2026-09-30用户明确批准实施；不是实盘交易授权或已完成声明。沿用现有目录约定，不迁移、不删除原账户和历史证据。

## 目标与本次核查结论

目标是验证用户能手工执行的少持仓、低频、中长期策略，而不是证明程序能下第一笔单。维持已批准的L1/R1、研究资金及风险参数；盈利有效性仍待真实前向样本验证。

已读取的实现证据：

| 环节 | 现有能力 | 必须补齐的运行缺口 |
| --- | --- | --- |
| 买入 | manual_first_execution及check_manual_execution支持单订单、初始空账户 | 后续订单读取当前账户而非重新用初始现金；保留首笔原件 |
| 持有与退出 | manual_rules.exit_decision已有规则 | 当日证据、持有交易日、复权含息收益、连续完整周数据尚需接入；未知必须REVIEW |
| 买卖记账 | manual_execution.execute_signal与share_account支持买卖、费用和批次 | 持久事件链、重放、前后余额校验、重试幂等与崩溃恢复 |
| 公司行动 | cash_dividend_account、dividend_ledger、account_reconciliation可复用 | 公告资格、登记持仓、到账与税务事件顺序接入；未覆盖的送转/税项显式阻塞相关计算 |
| 报告 | manual_account_report只有首笔范围 | 多事件逐日净值、期间损益、卖出及分红、回撤与缺口状态 |
| 开源借鉴 | 当前策略文档记录四个参考项目 | 固定提交版本和许可证正文，映射到本地规则；旧Qlib轮动不回到主线 |

不得把已有底层函数等同完整运行链，也不得通过测试结果声称策略赚钱。

## 实施顺序与边界

1. **只读重放与兼容导入视图。** 首批run及已发生终态作为只读根事件，绑定原文件哈希；不复制成第二笔成交、不修改原文件。不做数据库schema或数据迁移。重放必须与原现金、持仓、费用逐项一致。
2. **追加式日终账户与估值。** 新产物放`reports/manual_account_cycle_<UTC时间戳>/`，含event.json、account.json、manifest.json。每事件绑定上一可信事件哈希、来源、规则版本、实际时点和逻辑幂等键。进程锁内检查已有提交；最终manifest作为提交标记，未完成目录不自动当成功，也不能直接跳过可能成交的半成品。重复执行只读取已有结果。遇冲突停止并留痕，不删除目录。
3. **每日持仓审阅与退出订单。** 从实际成交批次计算持有交易日；公告与公司行动先核验，信号与执行分离。复用原退出规则，不创造新止损或盈利目标。明确交易日历中的周末/节假日最后交易日。风险退出优先，无法成交保留持仓与待处理风险；任何新执行尝试必须有新的当时证据，不追填失效价格。
4. **公司行动及对账。** 登记日资格来自真实模拟持仓；应收、到账、税费和卖出按时序入账。现金到账不可倒灌到之前交易。分红税未明确时分别标注税前/税款未决，不能宣称税后可比收益。未覆盖事项停止受影响账户计算并出异常，不擅自简化为无事件。
5. **统一报告与复盘。** 纯读事件与估值生成日报、周内/月内或完整周期报告，区分当期与累计、已实现与未实现。净值缺口不填零，停牌/休市的末次价格显式标明日期，不假称今日有效成交价。只有覆盖完整的净值序列才计算区间回撤；基准口径不匹配不计算超额收益。复盘输出数据问题、执行问题、策略假设及不调整/候选提案，不自动修改正式版本。
6. **复核开源来源并接续真实运行。** 优先复核当前文档已选来源，不重做宽泛搜索；记录固定提交、许可证与借鉴边界。先用隔离测试场景验证整链，再对真实原账户只读对比，验证后接入现有早晚检查。不能为验收主动制造真实候选卖出；完整自然持有和退出证据须随市场累积。

业务层继续放src/ashare_lab/selection，tools仅编排，tests隔离合成数据。原manual_forward、manual_execution、manual_paper目录不覆盖。策略变更提案继续放docs，含版本、证据、失败标准及独立验证记录。

## 验收标准

- 原首笔及全部已有事件重放余额相符；重复运行和中断恢复不会重复入账。
- 隔离测试覆盖买入、持有、卖出、T+1、停牌/涨跌停拒绝、失效订单、缺估值、公司行动、税款未决、跨月以及损坏来源。合成结果不混入真实收益。
- 实际日报由真实账本生成，订单/成交/拒绝/撤单、现金、股数、费用、有效价格来源可追溯；报表独立复算一致。
- 左侧和右侧机制有源码来源或独立实现说明，不能用引擎许可证替代策略有效性证据。
- 运行验收和盈利评价分开：即使系统验收通过，没有足够真实持有及退出样本仍明确“证据不足”。观察期和晋级样本门槛需事前另行提出，不能看完收益再设。

## 风险、成本与审批

### 已实施进度（2026-09-30，未完成整链）

当日估值审阅接口：`tools/check_manual_account_cycle.py --review reports/<审阅>.json`。审阅含account_id、day、reviewed_at、codes（当前全部持仓代码）、ledger_complete与corporate_actions_verified（true/false/null）、rationale、ledger_sources（当前入口读取的完整来源映射）、source_hashes（全部审阅证据）、quote_paths（证券到封存quote.json路径）。两项结论为true时必须有理由；公司行动结论必须列action_sources并绑定到source_hashes，不能用行情文件本身代替公司行动证据。未知仍输出缺口。审阅时间不得晚于运行或早于绑定资料形成时间。入口只读，不记录新成交；此接口不复用盘前资格作为全天公司行动核验。

正式推荐约束：观察名单不进入推荐栏目；每个正式推荐必须有唯一`recommendation_id`，且等于同一账本中的`order_id`，同时存在模拟成交、拒绝、等待或过期事件之一。报告生成器只从已登记订单生成推荐，校验`BOUND_TO_SIMULATION_ORDER`；没有订单绑定的推荐属于错误。这样推荐与模拟交易不会脱节。

- `manual_account_replay.py`提供原首笔事件的只读账户重放；调用入口仍必须核验manifest与来源绑定。已对现有5条等待事件重放核对现金10万元、零成交、零持仓，未重复记账。
- `manual_daily_valuation.py`提供纯计算估值：要求当日账本审阅、公司行动确认、收盘后且当日有效报价。来源封存由适配入口核验，函数不冒充已完成该核验。缺数据输出INCOMPLETE而非虚假零收益；存在已确认分红时税款未评估，不输出最终税后收益率。
- 上述模块尚未接入持久化日循环、正式报告和卖出调度。停牌/休市沿用价估值政策尚未接入，当前保守显示缺口；不能声称持续运行已完成。

主要风险是事件顺序、公司行动或复权处理错误导致收益失真；追加存证与独立重放增加实现及维护成本。少持仓放大个股风险，低频验证耗时；本方案不保证收益、不授权实盘。

请求批准上述持续账户接入范围，不要求用户现在确定实盘资金；不包含新全局依赖、系统配置、密钥、推送、公开发布、数据库迁移或删除。批准后分步实现并验证，任何进一步改变策略参数/扩大权限另行决策。已有首笔按原冻结规则正常等待执行证据，不因本方案等待审批而重建订单。
