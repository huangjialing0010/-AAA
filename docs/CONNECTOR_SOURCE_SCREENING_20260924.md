# 外部规则数据源初筛

## 当前结论

暂不直接接入任何新来源。现有 BaoStock 快照和适配器只提供基础日线字段，不能解除当前规则证据闸门。

本轮 GitHub 筛选后，新增一个可先做离线验证的候选：
`holdout-labs/ashare-data-immunity`。它是 MIT 许可的 A 股日线质量检查工具，能按板块和日期规则从已有 OHLCV 推算涨跌停事件、识别停牌启发式，并生成 SHA-256 快照；它本身不抓取数据，也不提供交易接口。因此它可以作为“规则计算/质量审计层”的借鉴对象，但不能替代逐日外部规则快照，也不能单独解除实盘或纸上账户准入。

另一个更接近“数据接口”的候选是 `FTShare-python-sdk`，其 GitHub 文档列出 `stk_limit` 风格的逐日涨跌停价字段（`pre_close`、`up_limit`、`down_limit`），但使用托管服务需要 API Key；仓库 MIT 许可只覆盖 SDK 代码，不自动覆盖托管数据的额度、授权或再分发权。当前仅登记为 `UNAUTHORIZED_CANDIDATE`，不安装、不请求、不导入。

公开文档中有第三方 API 声称提供“历史涨跌停价格”接口，但需要 Token 和独立套餐/频率核验；目前只登记为候选，未把演示接口当作数据证据。

本次只读打开演示 URL 未能取得可解析响应，因此该来源目前仍是 `UNVERIFIED`，不能进入导入或回放。

## 接入准入

候选来源必须先通过：字段完整性、历史覆盖、重叠日期、SHA256 封存、许可和失败可见性检查。未完成前不能解除 `NOT_READY_FOR_PAPER_ACCOUNT`。

## 推荐顺序

1. 先借鉴 `ashare-data-immunity` 的规则计算和快照审计思路，在本地已有数据上做“规则推算 vs 外部样本”的重叠日误差报告；这一步不需要新增账号或网络数据。
2. 再择一获得授权的逐日规则数据源（FTShare/Tushare 兼容接口或 WorkBuddy/飞书导出），只导入一个小窗口做字段、覆盖、SHA256 和回放验证。
3. 两者重叠验证通过后，才允许扩大导入范围；在此之前继续保持 `PAPER_REPLAY` 和 `live_admission` 阻断。
