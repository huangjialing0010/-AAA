# 财务公告事件数据契约（V1 草案）

状态：设计草案，未实现、未获准入正式回测。

## 目的与边界

当前 `data/canonical/financial_reports/` 是按证券与报告期归档的财务快照，`available_date_assumed` 是保守代理，不记录同一报告期的初版、预告/自愿披露、正式报告和更正值之间的版本关系。本契约定义独立的追加式公告事件层；不覆盖旧快照、不变更策略、不改变既有财报代理日期，也不自动宣称任何候选数据已满足正式回测准入。

首轮只设计300774、001389、603139三个已发现异常案例。只有来源可追溯、公告内容及时间语义可复核后，才讨论实现导入器或扩大范围。

## 分层与文件布局

```text
data/imports/financial_disclosure_events_pilot_<UTC时间>/
├── manifest.json                 # 来源、采集方法、许可/使用限制、文件哈希与范围
└── source_documents/             # 原始公告文件或合法保存的原始响应；只读

data/canonical/financial_disclosure_events_v1/
├── events.csv                    # 一条公告/披露事件一行
├── facts.csv                     # 一条事件中的一个标准化财务字段一行
└── manifest.json                 # 输入清单哈希、转换器版本、输出哈希、质量状态
```

若来源不允许保存公告文件，不得绕过；原始层改为保存允许留存的来源标识、官方 URL、采集时间、响应哈希和许可说明，并在清单中标明“未保存原文”。无法满足可审计性时，该事件不得进入正式点时回测。

### 来源使用限制（2026-09-28初查）

- 东方财富现行[用户服务协议](https://about.eastmoney.com/home/protocol)对其产品与服务内容及行情数据复制、提供和衍生使用设有限制；其[Choice产品许可协议](https://choice.eastmoney.com/html/userprotocol/userprotocol.html)明确限制未经书面同意从该产品服务器爬取数据。Choice协议是否适用于公开网页上的财报接口不能仅凭现有文本下结论，但在核对该接口适用条款前，不新增自动化批量抓取或再分发行为。
- 巨潮资讯当前查到的[App隐私政策](https://static.cninfo.com.cn/cninfoapp/strategy/privacy.html)不是数据抓取、保存或再利用许可；巨潮网站/公告文件适用的使用条款、批量访问限制及保存范围仍需单独确认。
- 这是来源治理初查，不构成法律意见，也不等同于取得任何授权。只有官方明确许可、取得书面许可，或选定许可清晰的数据供应方式后，才可批准相应自动化采集范围。

## `events.csv` 字段

| 字段 | 语义 |
|---|---|
| `event_id` | 稳定唯一键；由证券代码、报告期、事件类型、官方文件哈希组成，不用抓取顺序生成 |
| `security_code` | 六位证券代码字符串，保留前导零 |
| `report_period` | 财务所属期，ISO 日期；不是公告可用日 |
| `event_type` | `preliminary`、`voluntary_partial`、`periodic_report`、`correction`、`restatement`、`other`；不确定时 `unknown` |
| `version_label` | 来源可证实的版本标签；无法判断则 `unknown`，不自行推断 |
| `supersedes_event_id` | 被本公告明确替代/更正的事件；不确定或未发现时为空 |
| `publication_timestamp` | 来源明确给出的发布时间，保留原始时区偏移；不得把日期伪造成时分秒 |
| `publication_date` | 官方公告日期；与发布时间分开保存 |
| `time_precision` | `second`、`minute`、`date_only`、`unknown` |
| `source_name` / `source_url` | 权威披露来源及原始链接 |
| `source_document_sha256` | 被保存原件的哈希；未保存原件时为空并解释原因 |
| `source_document_status` | `archived`、`url_only`、`unavailable`、`review` |
| `is_preliminary` | `true`、`false`、`unknown`；仅依据公告原文判断 |
| `captured_at` | 采集时间，ISO 8601 含时区；不得作为公告时间 |
| `review_status` | `PASS`、`REVIEW`、`REJECT`；只有 `PASS` 可被后续准入逻辑考虑 |
| `review_note` | 简短记录原文依据、冲突或限制，不填臆测结论 |

## `facts.csv` 字段

| 字段 | 语义 |
|---|---|
| `event_id` | 外键，必须存在于 `events.csv` |
| `metric_name` | 标准字段名，如 `net_profit_parent`；保留指标层级（合并/母公司） |
| `raw_label` | 公告原文中的字段名称 |
| `raw_value` | 原始展示值；原文缺失、破折号、`False` 等缺失语义不得变成0 |
| `normalized_value` | 统一单位后的数值；不能可靠解析时为空 |
| `unit` | 明确记录元、股、百分比等单位 |
| `scope` | `consolidated`、`parent`、`unknown` 等口径 |
| `value_status` | `reported`、`not_disclosed`、`unparseable`、`conflict` |
| `source_locator` | PDF页码/表格行列或响应字段名，支持复核 |

事件元数据和财务事实分表，可以表达一份公告含多个指标，也可以表达更正公告只更正部分指标。未经原文核验的聚合快照字段不能伪装成逐事件事实。

## 时间映射与点时读取

1. 原始公告日期、原始时间戳和采集时间分别存储；禁止用 `UPDATE_DATE`、`NOTICE_DATE`、`EITIME` 任一单字段代替官方事件时间。
2. 策略若仅在日线收盘后生成信号：明确发布时间早于该交易日开盘时，可从该日收盘信号开始评估；发布时间在开盘后、盘中/收盘附近，保守地从下一交易日信号开始；只有日期或时间不明时，从公告日期之后的下一交易日开始。交易日由封存的交易日历决定。
3. 信号日期只读取当时已公开且 `review_status=PASS` 的事件。若多个版本依次披露，选截止时点之前最新、且版本关系可证实的事件；不得用后续版本回填早期截面。
4. 对策略调仓日还要应用其固定信号截止时间；公告虽在某日可用，但晚于策略当日决策截止时，不得进入该次调仓。
5. 在 `publication_timestamp` 或官方来源冲突无法解释时标记 `REVIEW`，对应事实不得进入正式回测。

## 必须通过的质量闸门

- `event_id` 唯一，事实外键完整；证券、报告期、来源及单位可解析。
- 事件时间有来源依据；公告时间不能早于报告期，若来源确实如此则停止并人工复核，不静默丢弃。
- 保存原件时哈希重算一致；原始文件和导入清单只读，不原位修订。
- 同一公告中的字段值与原文定位可复核；同名指标口径不一致时不得合并。
- 更正/重述以新事件追加，不能覆盖旧事件；版本图无环，引用到的前置事件存在。
- 有日期冲突、原文无法获取、版本关系不明、指标口径不明时采用 `REVIEW`/`REJECT`，不得靠推测放行。
- 只有三案例逐条通过独立复核后，才考虑小规模导入实现；通过小样本也不等于全市场来源验证完成。

## 三案例首轮验收问题

- 300774：能否分别复现2026-03-17初版与2026-04-04更正版本的归母净利润，并验证点时查询在两日期之间只返回初版。
- 001389：能否区分2026-02-28未经最终审定的部分数据与2026-03-28正式年报；不得默认把前者当完整年报。
- 603139：无法解释的 `EITIME` 仍是 `REVIEW`；只有找到对应原始事件及版本证据后才能定级，否则保留未知、不进入点时值选择。

## 风险与代价

- 官方公告逐份核验和版本追踪比批量抓取当前截面慢，首轮股票与字段覆盖会明显较小。
- 官方网站可访问不代表允许批量抓取、长期保存或再分发；东方财富与巨潮来源条款目前尚未形成足够的自动化采集授权结论，不能把既有试验快照或接口可访问性视作许可。
- PDF解析可能产生单位、合并/母公司口径或负数符号错误；原文定位和人工复核增加成本，但不可省略。
- 事件模型能降低版本覆盖导致的未来函数风险，不能解决历史股票池偏差、财报缺失、会计口径变化或行情可成交性问题。
