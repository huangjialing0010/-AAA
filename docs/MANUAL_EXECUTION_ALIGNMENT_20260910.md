# 中长期、自动虚拟盘与手动实盘目标对齐

## 用户目标

借鉴 GitHub 可追溯策略或工程组件，建立自己的选股系统；自动虚拟盘验证后，由用户手动实盘。偏好中长期、低操作负担，同一股票通常三天或更久才操作一次。不设计券商自动下单。盈利是评估目标，不是可承诺的系统验收结果。

## 已核查的匹配与缺口

当前主策略设计为月末信号、下一交易日成交，月内不因排名变化交易、不追被拒订单。

对封存研究运行 `stock_selection_mvp_20260909T024729Z_short5` 的主策略成交文件执行 `tools/audit_manual_cadence.py`，进程退出码 0：2013-01-04 至 2026-09-01，共 165 个成交日、5,888 条成交记录。同一证券不同成交日最短间隔 22 个自然日，无小于三个自然日的间隔。每成交日笔数中位数 35、最大 48。

这证明历史研究记录低频，但不证明手动执行方便。30 只股票的集中调仓仍可能产生较大工作量；名义金额研究成交也不能代表真实股数账户订单。

## 后续验收要求

1. 保持原研究参数和证据，不为了手动便利悄悄减少持股数后沿用旧收益。
2. 真实虚拟账户额外报告每月操作日数、单日买卖笔数、同股操作间隔、换手及拒单；自然日与交易日分开标注。
3. 每次提供可人工执行的买卖清单、股数、参考价格时点、资金需求和原因；手工实际成交录入后独立对账，不将建议视为已成交。
4. 三天偏好暂按普通调仓的最低自然日间隔评估，不据此禁止紧急风险提示；特殊处置需显式列为例外，不能隐藏成日常频繁操作。
5. 自动数据更新、虚拟执行、对账与失败提示仍需实现并运行验证。不得把历史批处理冒充已经运行的前向自动虚拟盘。
6. GitHub 候选须补充持有期、换手与手动执行负担评价。原版日频模型保留原标签；低频改造单独命名与验证，不能声称原版复现收益。

## 代价和边界

减少持股可降低操作量但增加集中风险；降低换仓频率可能延迟响应；设置不交易区间可能减少细碎调仓但改变收益。以上均属于待比较方案，不在本次审计中改参数。真实账户和前向验证尚未完成，不进入手动实盘晋级。
