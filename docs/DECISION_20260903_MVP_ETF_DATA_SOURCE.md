# 510300 MVP历史行情数据源变更决策

状态：`APPROVED`（2026-09-03）。

## 发现的事实

1. BaoStock能够确认`sh.510300`为存续ETF，但日线只返回2026年数据；2012—2025三个查询窗口中的前两个为空。
2. 对510300请求`adjustflag=2`（前复权）时，BaoStock返回行仍标记为`adjustflag=3`，不能形成原设计要求的双口径数据。
3. GitHub上的AKShare `fund_etf_hist_em`当前实现使用东方财富公开K线接口；本次连续两次直接请求均在响应结束前断开。它可保留为后续候选源，但不适合成为本轮MVP唯一依赖。
4. Yahoo图表接口本次返回`510300.SS`自2012-05-28至2026-09-02共3,467个日期。与BaoStock 2026年162个重叠日期相比，前161日OHLC和成交量逐项一致；2026-09-02的Yahoo记录尚不完整，收盘价为空且成交量不同。
5. Yahoo返回13次分红事件，缺少2012-12-18首次分红；新浪复权因子与历史分红表共同给出截至2026-01-19的14次现金分红、累计每份0.880元。
6. 实施时发现Yahoo在2025-10-24保留了时间戳但OHLC和成交量全为空；新浪最近1023日日K包含该日完整行情。该日必须显式标记为新浪补缺，并用其余重叠日反向校验Yahoo，禁止静默填充。
7. 独立验收又发现Yahoo在2024-01-15、2024-03-29、2025-05-23存在异常OHLC或成交量。腾讯前复权日K的日内价差形状及成交量与新浪一致，支持判定Yahoo这3日异常；三日改用新浪值，并标记为第三来源已佐证的覆盖。

## 建议方案

采用“Yahoo原始行情 + 新浪14次分红 + BaoStock近期交叉验证”的三证据结构：

- Yahoo原始OHLC和成交量用于成交模拟，截止日退回最后一个完整且已被BaoStock交叉验证的交易日，即2026-09-01；
- Yahoo唯一空行情日2025-10-24由新浪日K补齐，标准数据记录逐行来源；新浪最近1023日同时用于第二组交叉验证；
- Yahoo另外3个异常日采用新浪值，腾讯只作为裁决证据封存，不直接成为成交价来源；
- 不直接相信Yahoo调整收盘价，也不再要求BaoStock前复权；
- 用新浪14次现金分红事件，从不复权收盘价内部构建总回报信号序列；
- BaoStock只保留证券身份和2026重叠期核对证据；
- 封存Yahoo与新浪原始响应、请求参数、抓取时间和SHA256，独立验收后才能回测。

该方案仍借鉴GitHub项目的数据适配器分层，但不安装AKShare或yfinance，也不复制其实现代码。

## 不采用的方案

- 继续依赖BaoStock ETF日线：历史覆盖不足且复权参数未生效，会制造虚假双口径。
- 立即依赖东方财富：本次源端断流，无法形成可复现快照。
- 改用沪深300指数当可交易标的：指数本身不可成交，会破坏交易费用和账本语义。
- 临时改成一只个股：能测试引擎，但与已批准的宽基ETF策略假设不同，并引入单股事件风险和幸存者偏差。

## 风险和代价

- Yahoo和新浪都是公开网页数据，不是交易所或基金管理人授权的数据服务，接口可能变更或停止。
- 腾讯也只是公开网页交叉证据；4个非Yahoo行情日必须在运行清单和报告中公开，未来正式资金阶段需重新核对。
- 同一研究链使用跨源数据，必须通过重叠期、分红公告和资产恒等式多重核对；不能仅凭接口返回成功就放行。
- 截止日从2026-09-02退回2026-09-01，损失一个不完整交易日，但避免把盘中或残缺数据当日终数据。
- 若未来进入真实资金决策阶段，必须重新接入更稳定且授权清楚的数据服务，并以基金管理人公告复核分红。

## 批准后的实施闸门

1. 改写510300抓取器和独立验收器；
2. 新快照至少包含3,466个完整交易日、14次现金分红、2012-05-28起始日；
3. 2026年与BaoStock重叠期除被排除的不完整末日外，OHLC和成交量必须完全一致（价格容差0.0001）；
4. 验收通过后，才进入T+1撮合、费用、分红应收和账本实现。
